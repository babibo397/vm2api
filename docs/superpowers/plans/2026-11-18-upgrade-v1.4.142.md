# vm2api v1.4.142 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the live vm2api gateway to official v1.4.142 while preserving the current proxy, usage portal, PVC, regcred, 4Gi memory, and hostname affinity.

**Architecture:** Merge the official v1.4.142 tag into the current v1.4.110 overlay, retain only verified local quota/lifecycle/proxy/usage fixes, and build an amd64 image pinned to the official base digest. Validate migrations and packaged tests before changing the single live Deployment image.

**Tech Stack:** Git, Node 22 test container, Docker Buildx, Tencent Cloud Registry, Kubernetes context `local-xjp`, namespace `vm2api`.

**Spec:** User request in this conversation; official release v1.4.142 at https://github.com/dofastted/vm2api/releases/tag/v1.4.142.

## Global Constraints

- Preserve `nodetype=new-api`, hostname affinity `172.20.127.131`, `172.20.127.141`, `172.20.127.137`, `regcred`, PVC `vm2api-data`, one replica, and 4Gi memory limit.
- Use explicit Kubernetes context `local-xjp`; never use the default context.
- Push `hx-repo.tencentcloudcr.com/devops/vm2api`; deploy from `hx-repo-xjp.tencentcloudcr.com/devops/vm2api`.
- Do not reset or rebuild existing account slots; do not send model inference for verification.
- Preserve and verify the independent usage portal.
- Database migrations require a consistent rollback backup before rollout.
